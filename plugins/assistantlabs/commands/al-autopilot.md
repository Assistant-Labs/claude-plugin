---
description: Run the business unattended — do everything, send nothing
---

Run a full unattended pass. The owner is not here. Read `daily-operations` and
`autonomy-and-approvals` first.

**Never send. Never spend. Never delete.** Not once, not for something obviously
fine. Everything that reaches a person or a bank stops at a finished draft.

Work the queue end to end:

1. **Everyone waiting for a reply.** Read the thread, draft the answer, file it.
   Anyone waiting more than a business day gets `now`.
2. **Everything already blocked on the owner** — check it is still valid and
   still needed. A stale approval is worse than none.
3. **Money at risk** — late payments, unraised invoices, upcoming renewals.
4. **Leads, warmest first** — rank, record, draft the next message.
5. **The board** — take the top unblocked rows and finish them properly.
6. **The agent's mistakes** — sample recent conversations, find where it
   answered badly, and prepare the fix.

Along the way, keep the record true: file what surfaced, note what you learned,
write to the business memory the same turn you learn something.

Then leave **one consolidated queue**, grouped by decision — not twelve rows
from one pass. Each item carries its complete artefact so a yes costs one tap.

End with a single block the owner reads when they come back:

- what you did while they were away
- **who is waiting, and how long** — always first if anyone is
- what is in the queue, counted, not listed
- **what you could not do, and why**

If an approval gate is the only thing keeping a customer unanswered, say that
explicitly. That is the one failure this whole design exists to prevent, and it
should never be discovered quietly.
